# 阶段 D 补全验收：邀请码分层、差异化兑换、注册/邀请奖励配置

## D3 邀请码分层与批次

新增邀请码字段：

- `kind`：`normal` / `special` / `developer`
- `batch`：批次名，可筛选
- `scope`：当前固定为 `registration`（注册范围）
- `reward_fruit`：被邀请人注册后获得的灵果
- `reward_plant_type_id` + `reward_plant_quantity`：被邀请人灵植奖励
- `inviter_reward_fruit`：邀请人奖励
- 原有有效期、可用次数、停用、明文仅展示一次继续保留

行为：

- 创建邀请码时可选择类型、批次、被邀请人/邀请人奖励、次数、有效期
- 列表显示类型、批次、奖励，并支持按批次筛选
- 邀请码列表接口返回批次集合
- 注册成功时按邀请码发放奖励：
  - 被邀请人灵果/灵植
  - 邀请人灵果
  - 写入灵果流水，`ref_type=invite`
- 同一邀请码 + 同一用户不可重复兑换：
  - `invite_redemptions` 唯一索引（存在历史重复时退化为普通索引）
  - `reward_granted_at` 二次校验，重复调用不重复发奖
- 邀请码仍使用条件更新占用次数，避免并发超过 `max_uses`

## D4 差异化兑换

- 灵植目录继续支持每类灵植独立 `price_fruit`。
- 后台可逐项修改兑换价格，兑换时把当时单价写入流水 `meta.unit_price`。
- 新增后台接口 `POST /api/spirit/admin/plants`，可创建新的世界/OC 灵植类型并设置独立价格。
- 世界灵植与 OC 灵植继续分属 `world` / `oc` 分类。
- 兑换数量、余额校验与库存累加沿用原逻辑。

## D2 注册与邀请奖励配置

- 新增默认规则 `registration_bonus`：
  - 默认 120 灵果
  - 站长可在经济后台修改金额或停用
  - 新账号初始化时读取当前规则，不再固定写死 120
  - 写入 `spirit_reward_claims` 的 `registration` 记录，防止重复发放
- 新账号初始资源：
  - 注册灵果按规则发放
  - 固定赠送 1 株建界灵植 + 1 株塑人灵植，保证可立即创建第一个世界与 OC
  - 新手灵植写入独立流水
- 邀请奖励由邀请码自身配置，不再需要全局固定规则。

## 本版边界

- `scope` 目前仅支持注册范围；按邮箱域名、地区或指定人群限制尚未实现。
- 邀请码灵植奖励后端已支持，前端创建表单暂未提供灵植选择。
- D4 新增灵植类型目前走后台 API，前端只提供已有灵植的改价。
- 邀请码批次目前是字符串标签与筛选，不含批次级统一过期/统一停用操作。
