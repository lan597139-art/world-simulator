# 世界模拟器｜DSH 后续架构升级任务书（完整版）

> 版本：完整版（依据《世界模拟器 DSH 后续架构升级任务书——修订版》编制）
> 核心原则：**不重复建设已有功能，不擅自推翻现有数据结构和仍然有效的业务规则。**
> 平台方向：**取消人民币充值、现金消费、提现及相关资金结算服务，统一采用虚拟货币灵果作为平台资源消耗单位。**
> 执行纪律：**先审计现状并提交差异清单，再按确认后的范围分批实施；完成一条、验收一条，避免四条主线同时铺开。不得未经确认直接大规模重构或删除历史数据。**

---

## 0. 文档说明

本文档是 DSH 后续架构升级的总任务书，将升级工作整理为**四条架构升级主线**，并逐条明确：

1. **目标**——每条主线要达成什么；
2. **约束**——不得突破的边界与既定业务规则；
3. **实施顺序**——先做什么、后做什么、何时验收；
4. **验收标准**——如何判定该条主线真正完成。

每项工作统一标记为：**保留 / 修复 / 优化 / 扩展 / 新增 / 删除 / 迁移 / 待决策**。
任何超出本任务书范围的改动、定价与结算规则，均须先形成待确认清单，不得擅自确定。

## 1. 基本背景（现状基线）

世界模拟器现有工程已具备部分相关能力，本次升级是**在原有能力上的增量架构升级**，而非从零重建：

| 现有能力 | 现状 | 本次定位 |
| --- | --- | --- |
| Local-First | 已有作品导出功能，尚未形成完整的本地优先架构 | 在导出功能基础上补齐本地存储、离线与恢复体系 |
| BYOK AI | 已有 API 模型密钥配置与调用能力 | 审计并统一全场景 AI 接入，消除重复实现 |
| AI 助手 | 已有前端人格、世界可视化编辑及捏 OC 功能，但原生 AI 助手后端人格管理较粗糙 | 保留前端编辑器，重点完善后端人格管理链路 |
| 资源系统 | 已有灵果、灵植及相关资源功能 | 在原有功能基础上调整和完善，取消原有现金商业体系 |

**硬约束**：不得重复建设已有功能，不得擅自推翻现有数据结构和仍然有效的业务规则。
**平台资金方向**：平台取消人民币充值、现金消费、提现及相关资金结算服务，统一采用虚拟货币灵果作为平台资源消耗单位。

---

## 2. 总体目标

在不破坏现有业务的前提下，完成**四条主线的增量架构升级**，使本地优先、AI 接入、人格管理、虚拟货币四条能力各自闭环、边界清晰、可独立验收：

1. **Local-First + PWA 本地优先架构**；
2. **全场景 BYOK AI 统一接入**；
3. **平台原生 AI 助手后端人格管理**；
4. **纯虚拟货币与创作体验服务体系**。

**平台产品服务统一围绕三个主要方向组织**：

- **创作**：创建、编辑和管理世界、OC、小说、故事线等内容。
- **体验**：消耗灵果浏览和体验其他用户创作的作品及 OC。
- **社区**：内容发现、关注、互动及创作者交流。

---

## 3. 四条架构升级主线（总览）

| 主线 | 名称 | 一句话目标 | 现状起点 | 主要性质 |
| --- | --- | --- | --- | --- |
| 一 | Local-First + PWA 本地优先架构 | 创作数据本地化、可离线、可恢复、可合并 | 已有作品导出 | 扩展为主，含新增 |
| 二 | 全场景 BYOK AI 统一接入 | 统一所有 AI 场景的服务商/密钥/请求/流式/错误处理 | 已有 API 接入 | 优化为主，含统一化改造 |
| 三 | 平台原生 AI 助手后端人格管理 | 人格数据后端化、可读取、可入模型上下文、权限可控 | 前端人格较完善、后端粗糙 | 修复 + 新增为主 |
| 四 | 纯虚拟货币与创作体验服务体系 | 统一灵果货币、取消现金体系、灵植规则保留、服务端资源安全 | 已有灵果/灵植功能 | 优化 + 删除 + 迁移 + 待决策为主 |

四条主线**共享能力（如 AI 接入、资源体系）各自独立，但业务数据、权限、账本不得混用**。

## 4. 各主线详细要求

### 4.1 主线一：Local-First + PWA 本地优先架构

**目标**
在现有作品导出功能基础上，形成完整的本地优先能力：创作数据本地存储、本地读写与自动保存、离线查看与编辑、离线启动，以及导入、备份、恢复、版本管理与差异合并。

**具体工作**
| 编号 | 工作项 | 标记 |
| --- | --- | --- |
| L1-1 | 创作数据本地存储，重点评估 IndexedDB | 新增/优化 |
| L1-2 | 世界、OC、小说、故事线等数据的本地读写与自动保存 | 扩展 |
| L1-3 | 离线查看、离线编辑及 PWA 离线启动 | 新增 |
| L1-4 | 数据导入、备份、恢复和版本管理 | 扩展 |
| L1-5 | 本地与导入数据的差异比较、冲突检测及用户确认合并 | 新增 |
| L1-6 | 明确本地数据与服务端权威数据的边界 | 修复/新增 |

**约束**
- **第一阶段不要求实时双向同步**。
- **不得未经用户确认覆盖本地数据**；任何合并、覆盖、回滚均须用户明确确认。
- 本地数据与服务端权威数据的边界须显式定义，本地数据不得静默反写服务端权威数据。

**验收标准**
- 本地保存、离线编辑、离线启动在真实浏览器中实际可用（不以构建成功代替功能验收）。
- 导入、备份、恢复、版本管理可端到端走通。
- 差异比较与冲突检测可识别冲突，且合并/覆盖必须经用户确认，无静默覆盖。
- 本地与服务端数据边界清晰，符合设计约定。

---

### 4.2 主线二：全场景 BYOK AI 统一接入

**目标**
基于现有 API 接入能力，审计并统一全部 AI 场景的接入链路，消除重复实现，统一服务商适配、模型配置读取、请求构造、流式输出和错误处理，同时保证 API Key 的安全与合规，且 AI 调用不构成平台虚拟货币消费项目。

**具体工作**
| 编号 | 工作项 | 标记 |
| --- | --- | --- |
| L2-1 | 确认 AI 助手、AI 角色扮演、AI 辅助写作是否全部接入 | 审计 |
| L2-2 | 检查不同场景是否重复实现 API 调用逻辑 | 审计/修复 |
| L2-3 | 必要时统一服务商适配、模型配置读取、请求构造、流式输出、错误处理 | 优化 |
| L2-4 | 保留各场景独立的 Prompt、上下文和业务逻辑 | 保留 |
| L2-5 | 审计 API Key 存储、传输、日志脱敏和第三方数据传输边界 | 审计/修复 |

**约束（业务规则）**
- **所有 AI 场景均由用户自行配置第三方 API。**
- **用户自行承担 API 服务商收取的费用。**
- **平台不提供自有模型服务，不提供免费 AI 额度。**
- **AI 调用不消耗灵果，不建立 AI 专属资源账户。**
- **AI 接入能力可以共享，但不得将 AI 调用设计为平台虚拟货币消费项目。**
- 统一接入层不得改变各场景既有的 Prompt、上下文和业务逻辑；统一只发生在接入底层。

**验收标准**
- AI 助手、AI 角色扮演、AI 辅助写作三类场景均经统一接入层使用用户自行配置的 API，无场景级重复实现。
- 三类场景业务身份独立，配置与调用互不串扰。
- 流式输出、错误处理在真实调用中表现一致。
- API Key 的存储、传输、日志均脱敏，第三方数据传输边界清晰，无密钥明文泄露路径。
- **AI 调用不扣除灵果，不存在 AI 专属资源账户，AI 接入未被设计为虚拟货币消费项目。**

### 4.3 主线三：平台原生 AI 助手后端人格管理

**目标**
保留现有前端人格与世界编辑器，不重新开发编辑器；重点完善**后端**人格数据结构与人格库，使人格数据可保存、可同步、可读取、可实际进入模型请求上下文，并具备权限与版本能力。

**具体工作**
| 编号 | 工作项 | 标记 |
| --- | --- | --- |
| L3-1 | 审计前端人格数据与后端的保存、同步和读取链路 | 审计/修复 |
| L3-2 | 完善后端正式人格数据结构及人格库 | 新增/优化 |
| L3-3 | 确保人格与世界设定能够被运行时正确读取 | 修复 |
| L3-4 | 确保人格设定实际进入模型请求上下文 | 修复/验证 |
| L3-5 | 完善开发者编辑权限和普通用户只读权限 | 修复/扩展 |
| L3-6 | 根据现有实现补齐缺失的草稿、发布、版本记录和回滚能力 | 新增/扩展 |

**约束（三类 AI 业务严格区分）**
- **平台原生 AI 助手**：开发者定义和维护人格。
- **用户自建 OC**：用户创建和维护人格。
- **AI 辅助写作**：由任务和上下文驱动，不强制要求独立人格。

三者**共享 API 接入能力，但不混用人格数据、权限和业务逻辑**。

**验收标准**
- 平台原生 AI 助手能从后端读取正式人格，并**实际用于模型调用**（验证人格设定确实进入模型请求上下文，而非仅存于前端）。
- **普通用户不能通过直接调用后端接口修改平台人格**（权限校验在服务端强制生效）。
- 草稿、发布、版本记录、回滚能力按现有实现补齐并可用。
- 三类 AI 业务的人格数据、权限与业务逻辑相互隔离。

---

### 4.4 主线四：纯虚拟货币与创作体验服务体系

**目标**
基于现有灵果、灵植系统进行审计和优化，**取消原有现金商业体系**；统一以灵果作为平台虚拟货币；保留既有灵植创作消耗规则；将体验中心调整为纯灵果消耗体验服务；删除内容商城与游戏体验中心；所有资源变更由服务端保障安全与可追溯。

#### 4.4.1 取消的商业功能（取消现金商业体系）

全面审计并处理以下旧功能及其依赖：

| 编号 | 待取消/处理项 | 标记 |
| --- | --- | --- |
| L4-1 | 灵石账户及灵石资源体系 | 删除/迁移 |
| L4-2 | 人民币充值及充值记录 | 删除/迁移 |
| L4-3 | 现金消费及支付接口 | 删除 |
| L4-4 | 灵石提现及相关审核流程 | 删除 |
| L4-5 | 创作者人民币收益账本 | 删除/迁移 |
| L4-6 | 作品人民币销售订单 | 删除/迁移 |
| L4-7 | 现金打赏、支付分账及结算 | 删除 |
| L4-8 | 虚拟资源兑换人民币的接口 | 删除 |
| L4-9 | 与上述业务绑定的页面入口、数据模型、服务端接口及后台管理功能 | 删除/迁移 |

**约束**
- **不得只隐藏前端入口而保留无用的现金业务链路。**
- **历史数据需要先审计并明确保留、归档或迁移方式，不得直接删除历史账本和流水，不得未经确认破坏已有用户数据。**

#### 4.4.2 统一虚拟货币体系

平台统一使用**灵果**作为虚拟货币。

**新账户初始资源**：
- **500 灵果。**
- **1 株世界灵植。**

**需要落实**：
| 编号 | 工作项 | 标记 |
| --- | --- | --- |
| L4-10 | 新账户初始化发放规则 | 新增 |
| L4-11 | 灵果余额和资源流水 | 优化 |
| L4-12 | 灵果发放、消耗及来源记录 | 优化 |
| L4-13 | 服务端资源校验 | 修复/优化 |
| L4-14 | 资源变更事务一致性 | 修复/优化 |
| L4-15 | 防止重复提交和并发超扣 | 修复 |
| L4-16 | 用户资源变更的可追溯记录 | 优化 |

**约束**
- **不得新增灵石或其他人民币结算型资源账户。**
- 不同来源的灵果仍需保留必要的来源标记，至少能够区分**初始发放、系统赠送及其他实际存在的发放来源**；具体分类以现有业务和确认后的规则为准。

#### 4.4.3 灵植及创作消耗规则

在审计现有实现后，核对并**保留**以下既有规则：

- **OC 灵植：30 灵果/株，仅用于创建 OC。**
- **世界灵植：100 灵果/株，仅用于创建世界。**
- **每个 OC 消耗 1 株 OC 灵植。**
- **每个世界消耗 1 株世界灵植。**
- **OC 与世界灵植库存独立。**

**补充规则**：
- **新账户直接获得的 1 株世界灵植应进入对应世界灵植库存，不应再次扣除 100 灵果。**
- **创建前检查资源库存、账户状态及创建权限；创建成功后扣除对应灵植；创建失败不得扣除资源。**
- **不得将 OC 灵植和世界灵植混用。**

#### 4.4.4 体验中心

将原「消费体验中心」调整为**「体验中心」**。体验中心**仅承担用户消耗灵果体验他人创作内容**的功能。

**保留方向**：
- 浏览和体验其他用户的作品。
- 体验其他用户创建的 OC。
- 根据实际可实现的产品能力扩展其他内容体验。

**需要审计**：
| 编号 | 工作项 | 标记 |
| --- | --- | --- |
| L4-17 | 现有作品体验与 OC 体验功能 | 审计/优化 |
| L4-18 | 灵果消耗入口及服务端扣除逻辑 | 审计/修复 |
| L4-19 | 体验权限与资源校验 | 审计/修复 |
| L4-20 | 体验记录及资源流水 | 优化/扩展 |
| L4-21 | 体验内容的作者归属和访问权限 | 审计/修复 |
| L4-22 | 体验前后的实际业务状态 | 审计/验证 |

**约束**
- **体验行为是否收费、具体消耗数量、不同内容的定价及创作者是否获得灵果收益，必须根据现有实现和产品确认结果确定，不得自行编造。**
- **删除原游戏体验中心及相关游戏体验功能。当前游戏体验能力无法实现，不纳入本次升级范围。**

#### 4.4.5 删除内容商城

**删除**原内容商城及其相关产品入口，包括：

- 商品展示与商品管理。
- 作品商品化销售。
- 购买与订单流程。
- 商城支付及退款。
- 创作者店铺及现金销售收入。
- 与商城交易绑定的前端入口和服务端业务。

**约束**
- **如果现有作品体验功能依赖商城中的部分内容数据或接口，应先审计依赖关系，再迁移必要能力，不得因删除商城而破坏已有作品数据和体验功能。**

#### 4.4.6 资源体系安全

**所有灵果和灵植的发放、扣除、兑换及创建消耗均由服务端执行。**

**服务端负责**：
- 身份和账户状态校验。
- 资源余额和库存校验。
- 业务权限校验。
- 资源变更和业务结果的事务一致性。
- 防重复提交和并发超扣。
- 失败回滚。
- 完整流水和来源追踪。

**约束**：**前端不得自行修改账户余额、灵植库存或交易结果。**

#### 主线四验收标准
- **平台不再提供灵石、人民币充值、现金消费、提现及现金交易服务。**
- **新账户能够正确获得 500 灵果和 1 株世界灵植。**
- **OC 灵植、世界灵植及其创建消耗规则正确执行。**
- **体验中心能够按确认后的规则完成作品和 OC 体验及灵果扣除。**
- **游戏体验中心和内容商城不再作为现有产品功能提供。**
- **不存在通过旧接口绕过新资源规则的路径。**
- **灵果、灵植交易具备服务端校验、事务一致性和可追溯流水。**

## 5. 全局约束

1. **不重复建设**：已有功能一律保留或增量优化，不重做。
2. **不破坏现有业务**：不得擅自推翻现有数据结构和仍然有效的业务规则。
3. **统一虚拟货币**：平台取消人民币充值、现金消费、提现及相关资金结算服务，统一以灵果作为资源消耗单位，不新增灵石或人民币结算型资源账户。
4. **清理须彻底**：不得只隐藏前端入口而保留无用的现金业务链路。
5. **历史数据审慎**：不得直接删除历史账本和流水，不得未经确认破坏已有用户数据；保留/归档/迁移须先审计明确。
6. **边界隔离**：灵果、灵植、历史现金数据相互独立；三类 AI 业务的人格/权限/业务逻辑相互独立；本地与服务端权威数据边界清晰。
7. **不擅自决策**：体验定价、灵果来源分类、历史现金数据处置等，一律先列待确认清单。
8. **安全合规**：API Key、密钥、日志脱敏，第三方数据传输边界清晰。
9. **不静默覆盖**：本地数据合并/覆盖、历史数据变更均须经确认。
10. **验收优先**：关键流程必须实际运行验证，不以代码存在或构建成功代替功能验收。

## 6. 实施顺序

**总纪律：先审计、再实施；完成一条、验收一条；避免四条主线同时铺开，降低相互干扰。不得未经确认直接大规模重构或删除历史数据。**

| 阶段 | 内容 | 说明 |
| --- | --- | --- |
| 阶段 0 | **全局现状审计**（四条主线只读审计，各自提交差异清单） | 审计为只读，四条可并行，不构成"同时铺开实施"；产出每条主线的现状审计与差异清单 |
| 阶段 1 | **主线二：全场景 BYOK AI 统一接入** | 基础层，改动集中、无数据迁移风险，为后续 AI 能力提供统一接入 |
| 阶段 2 | **主线三：平台原生 AI 助手后端人格管理** | 依赖主线二的统一接入能力，承接人格后端化 |
| 阶段 3 | **主线一：Local-First + PWA 本地优先架构** | 相对独立、工作量大，按子项分小批实施与验收 |
| 阶段 4 | **主线四：纯虚拟货币与创作体验服务体系** | 涉及旧现金链路清理、历史数据迁移与依赖风险，待确认清单确认后分批实施，最后闭环 |

**阶段内纪律**
- 每条主线内部按子项逐个完成、逐个验收，不跨主线交织改动。
- 每个子项完成后：自检 → 提交变更记录 → 功能验证 → 标记验收结果。
- 只有涉及**旧功能冲突、数据迁移风险或架构依赖**时，才扩大检查范围；常规情况只检查本次任务涉及的部分。
- 阶段顺序与范围经确认后执行；**不得未经确认直接大规模重构或删除历史数据**。

## 7. 交付结果

1. 四条主线各自的**现状审计与差异清单**。
2. 需要调整的**架构图、数据结构及接口说明**。
3. 按实际缺口制定的**增量实施计划**。
4. 已实施功能及**代码变更记录**。
5. **自动化测试和真实浏览器验证结果**。
6. **旧现金商业体系的清理、历史数据保留及迁移说明**。
7. **灵果与灵植资源规则及体验中心业务规则说明**。
8. **尚未完成事项及其依赖关系**。

每项工作标记为：**保留、修复、优化、扩展、新增、删除、迁移、待决策**。

## 8. 验收标准（汇总）

- 不重复开发已有功能，不破坏现有业务。
- Local-First 数据能够按设计完成**本地保存、离线编辑和恢复**。
- 三类 AI 场景能够使用**用户自行配置的 API**，且**业务身份独立**。
- **AI 调用不扣除灵果，不建立 AI 专属资源账户。**
- 平台原生 AI 助手能够**从后端读取正式人格，并实际用于模型调用**。
- **普通用户不能通过直接调用后端接口修改平台人格。**
- **平台不再提供灵石、人民币充值、现金消费、提现及现金交易服务。**
- **新账户能够正确获得 500 灵果和 1 株世界灵植。**
- **OC 灵植、世界灵植及其创建消耗规则正确执行。**
- **体验中心能够按确认后的规则完成作品和 OC 体验及灵果扣除。**
- **游戏体验中心和内容商城不再作为现有产品功能提供。**
- **不存在通过旧接口绕过新资源规则的路径。**
- **灵果、灵植交易具备服务端校验、事务一致性和可追溯流水。**
- **关键流程有实际运行验证，不以代码存在或构建成功代替功能验收。**
