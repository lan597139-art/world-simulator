# 商业与服务中心

商业与服务中心是全局一级页面，从侧边栏「账户服务」进入，路由参数 `?page=business`。它与用户身份中心、内容社区、社区社交并列，不再复用归档页或弹层。

页面：`src/pages/BillingCenterPage.tsx`；样式：`src/styles/billing-center.css`；前端 API：`src/api/billing.ts`；后端：`backend/billing.py`；迁移：`M045_commercial_center.py`。

## 1. 页面结构

六个模块与需求一一对应：

| 模块 | 页面能力 |
| --- | --- |
| 会员中心 | 当前方案、月付/年付切换、三档方案对比、权益、开通/升级、续费提醒偏好 |
| 充值与账户余额 | 余额、累计消费、待支付订单、充值套餐、最近流水 |
| AI 用量管理 | 本月总调用、平台/自带 Key 拆分、会员额度进度、提醒阈值、30 天趋势、最近调用 |
| 支付与订单 | 全部/待支付/已支付/已取消筛选、继续支付、取消待支付订单 |
| 创作者结算 | 累计收入、可结算、待打款、已打款、规则、收款账户状态、结算记录 |
| 费用与服务记录 | 余额流水筛选、服务周期、CSV 流水导出 |

页面顶部展示当前余额、会员等级和支付模式。所有金额由后端账本返回，前端不自行计算余额。

## 2. 数据模型

`M045` 建立六张表：

- `billing_accounts`：余额、币种、AI 月度提醒阈值。
- `billing_memberships`：方案、状态、周期、到期时间、续费提醒偏好。
- `billing_orders`：充值/会员订单、金额、状态、支付方式、时间。
- `billing_ledger_entries`：只追加的余额流水，记录入账/扣款与支付后余额。
- `billing_ai_usage`：AI 调用次数、路由、平台/自带 Key、模型、状态码。
- `billing_settlements`：结算周期、总收入、平台服务费、净额、状态。

没有「余额字段可直接改」的接口；余额只能由充值入账和会员扣款等账务动作改变。

## 3. 支付与沙盒边界

项目当前没有接入微信、支付宝或 Stripe，因此充值提供**显式的本地沙盒**：

- 只在 `localhost / 127.0.0.1` 默认开启；远程部署默认关闭，避免任意用户自助增发余额。
- 可通过 `WS_BILLING_SANDBOX=1` 显式开启，`WS_BILLING_SANDBOX=0` 显式关闭。
- 充值接口必须携带 `confirm_sandbox: true`，页面在确认弹窗中明确说明「不会产生真实扣款」。
- 会员订单只能使用已有余额支付；余额不足返回 402，不会绕过。
- 关闭沙盒后，充值订单保持待支付，页面提示「支付通道未配置」。
- 真实接入时必须由服务端验签支付回调后变更订单状态，不能信任前端支付结果。

## 4. 后端接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/billing/overview` | 账户、会员、方案、套餐、用量、结算摘要、最近订单/流水 |
| GET | `/api/billing/orders?status=` | 订单列表，支持状态筛选 |
| POST | `/api/billing/orders` | 创建充值/会员订单（待支付） |
| POST | `/api/billing/orders/{id}/pay` | 余额支付会员，或本地沙盒充值 |
| POST | `/api/billing/orders/{id}/cancel` | 取消待支付订单 |
| PATCH | `/api/billing/membership` | 续费提醒偏好 |
| GET | `/api/billing/usage?days=` | AI 用量汇总、趋势、最近调用 |
| PATCH | `/api/billing/usage` | 设置月度调用提醒阈值（0 表示关闭） |
| GET | `/api/billing/records` | 余额流水与服务周期 |
| GET | `/api/billing/settlements` | 创作收入与结算单 |
| POST | `/api/billing/settlements/run` | 生成待打款结算单 |

所有接口要求登录。

## 5. AI 用量记录

AI 中间件在 AI 请求完成后记录一次调用：

- 路由白名单只覆盖真实 AI 调用，不记录普通 CRUD。
- 记录了平台 Key 与自带 Key 的来源区分、模型名、状态码；**不记录提示词、响应内容或 API Key**。
- 自带 Key 不占平台额度、不产生平台费用。
- 当前只做用量展示与提醒阈值，不自动中断个人 Key 调用。
- `WS_AUTH_DISABLED` 回归模式下不写用量，避免测试污染。

## 6. 创作者结算

- 结算资金来自 `creator_earning` 流水，而不是伪造前端数字。
- 平台服务费 10%，最低结算金额 ¥100。
- 生成结算单后进入 `pending`，当前未接入提现通道，页面不会假装已打款。
- 收款账户不做假绑定，不收集银行卡/身份证信息；待真实支付机构接入后再设计服务端实名与绑卡流程。
- 同一用户同时只允许一笔待处理结算单，防止重复申请。

- 充值订单、沙盒确认、入账、流水
- 会员订单、余额不足 402、充值后支付、会员额度更新
- 续费偏好、订单取消、取消后支付 409、状态筛选
- 流水与服务周期
- 创作收入汇总、结算单生成、重复结算 409
- AI 用量来源拆分与趋势

已加入 `backend/tests/run_all.sh`。
