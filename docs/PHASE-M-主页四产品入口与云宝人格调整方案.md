## 2. 差距清单

### P0（不解决就无法验收）

1. **没有独立主页**：根路径进入的是上一个产品的总览/人格页，而不是四产品选择页。
2. **产品导航有两套**：侧栏 `ProductSwitcher` 与工作台导航并列；总览内又有四张产品卡。
3. **云宝不存在**：无单一身份、无自传/成长/成熟度/当前状态字段。
4. **无所有者权限**：数据库、API、UI 都没有“系统所有者 vs 普通用户”。
5. **三种常态缺失**：当前仓库找不到状态切换实现，无法“复用”只能新增或接入外部设计。
6. **助手身份仍是“全局 AI 助手”**：昵称、头像、人格说明、会话归属都不是云宝。
7. **查看入口缺失**：助手面板不能跳到 03 并定位云宝。
8. **03 人物管理没有云宝卡片**：只有普通人物和旧人格入口。

### P1（影响一致性和数据安全）

1. 旧人格编辑器仍可创建多个身份，与“云宝只有一个 AI 身份”冲突。
2. 伴侣 `MemoryPage` / `CompanionRuntimePage` 面向多个人格，且普通用户可直接改状态、写/删记忆。
3. 助手会话按产品分键，切产品后云宝会话历史不连续。
4. 文学工作台包含 01 总览，与功能清单不一致。
5. 游戏总览统计中的模拟次数未按产品世界过滤；人物/事件统计使用硬编码地址与全量数据再过滤。
6. 产品切换器弹窗展示完整功能矩阵，对普通用户暴露内部模块配置，不是必要的主页体验。
7. 后端 `personas.py` 把所有者写死为 `local`，未来增加普通账号会越权。

### P2（本次不建议扩大范围）

1. 人物、事件、关系等既有 API 仍主要依赖 `world_id`，没有统一的“产品级服务端访问层”。本次只保证不破坏现有关系，不重构底层。
2. 没有普通用户开通/管理界面。本次只建立角色字段与服务端只读约束，不新增账号运营后台。
3. 云宝的多用户会话隔离、跨用户记忆隔离属于未来多租户议题；当前系统仍是单用户本地账号。

## 3. 目标信息架构

```
登录
└── 产品主页（home，无产品工作台导航）
    ├── 侧栏：四大产品入口（与主区四卡同源）
    └── 主区：四张产品卡
        ├── 🎮 游戏创作 → 游戏创作工作台
        ├── 📖 文学创作 → 文学创作工作台
        ├── 💬 AI 伴侣  → AI 伴侣工作台
        └── 📔 日记与传记 → 日记与传记工作台

产品工作台
├── 侧栏：返回产品主页 + 当前产品开放的功能分组
├── 顶栏：当前产品 / 当前世界 / 当前页面
└── 产品内部页面
    ├── 01 世界总览（仅游戏）
    ├── 02 世界管理（游戏/文学）
    ├── 03 人物管理（四产品均开放，模式不同）
    │   └── 云宝人格卡片（全局 AI，独立于世界人物）
    ├── ...
    └── 云宝详情（只读或所有者编辑）
```

### 3.1 路由规则

- `/`：产品主页。
- `/?product=game&page=overview`：游戏工作台深链。
- `/?product=literature&page=character-management`：文学工作台深链。
- 云宝查看：`/?product=companion&page=personas`，或从任意产品跳到
  `/?product=<当前产品>&page=character-management` 并定位云宝卡片。
- 未登录/登录过期仍由 `AuthGate` 拦截。

### 3.2 产品切换规则

- 主页点产品：设置产品、进入该产品 `home`，自动准备伴侣/日记隐藏空间。
- 工作台内不显示四产品完整导航；提供“返回产品主页”。
- 顶栏保留当前产品标识，可作为返回主页入口；不再放会展开完整配置矩阵的切换器。
- 从 A 产品进入 B 产品时清空不匹配的当前世界，避免串数据。
- 深链进入未开放模块时，路由守卫回到该产品 `home`。

## 6. 云宝人格方案

### 6.1 身份原则

- 云宝是**唯一**全局 AI 身份，不是世界 NPC，不是普通创作人物。
- 三种常态是同一 `persona_id` 的运行时状态，不是三条人格记录、不是三个 AI。
- 云宝拥有独立会话、记忆、自传、成长经历、当前状态。
- 云宝不属于某个产品；产品只决定从哪个入口查看/对话。

### 6.2 数据结构

在现有 `personal_personas` 上扩展，保留旧数据：

| 字段 | 类型 | 用途 |
|---|---|---|
| `system_key` | String nullable | 云宝固定为 `yunbao`；旧人格为 NULL |
| `maturity` | String | 人格成熟展示 |
| `biography` | Text | 自传 |
| `growth_experience` | JSON list | 成长经历 |
| `states` | JSON list | 三种常态定义 `{key,label,description,prompt_hint}` |
| `active_state` | String | 当前常态 key |
| `owner_user_id` | 已有 | 系统所有者；普通用户不拥有 |

沿用字段：

- `name`：云宝
- `identity`：全局 AI 人格定位
- `description`：自我描述
- `esa`：人格动力，仅所有者可改
- `traits`：表达/人格特征
- `cognition`、`expression`、`interaction`：表达特征与互动方式
- `memory_policy`、`public_profile`、`tools`
- `status`：运行/暂停

新增迁移 `M035_yunbao_profile`：

- `personal_personas.system_key TEXT` + 部分唯一索引
  `(owner_user_id, system_key) WHERE system_key='yunbao'`
- `personal_personas.maturity TEXT`
- `personal_personas.biography TEXT`
- `personal_personas.growth_experience JSON DEFAULT '[]'`
- `personal_personas.states JSON DEFAULT '[]'`
- `personal_personas.active_state TEXT DEFAULT ''`
- `app_users.is_owner INTEGER DEFAULT 0`
- 回填：`local` 账号 `is_owner=1`；旧人格保持 `system_key=NULL`，不合并、不删除。

启动时 `ensure_yunbao(db)` 幂等创建一条云宝记录；不迁移旧人格内容，避免把多个身份混成一个。

### 6.3 云宝卡片（03 人物管理）

位置：`CharacterListPage` 顶部，独立分组“全局 AI 人格”，与普通人物列表分开。

卡片展示：

- 头像 / 名称：云宝
- 身份：全局 AI 人格
- 人格成熟
- 表达特征摘要
- 自传摘要
- 成长经历条数 / 最近一条
- 当前状态（三种常态之一）
- 标签：`系统所有者维护`、`只读` 或 `可编辑`

交互：

- 点击卡片 → 云宝详情。
- 详情默认只读。
- 所有者额外显示“编辑人格”；普通用户不渲染编辑按钮和表单。
- 详情包含：身份、成熟度、表达特征、自传、成长经历、当前状态、ESA、特征、认知/互动、记忆策略、工具、运行状态。
- 普通用户可查看全部展示字段，但所有输入框/滑杆/保存/删除都不出现。

### 6.4 云宝详情入口

1. 03 人物管理 → 云宝卡片 → 详情。
2. AI 伴侣 → `云宝 · 个人 AI 人格`。
3. 任意页面打开云宝对话框 → “查看 AI 人格” → 03 人物管理，定位云宝卡片并打开详情。
4. 原有 `/personas` 模块改为云宝详情页，不再渲染“多个人格管理器”。

### 6.5 旧人格兼容

- `PersonaManager` 的多身份创建/模板/删除 UI 下线，避免用户再创建与云宝并列的“我的人格”。
- 旧 6 条人格、2 个会话、5 条消息、1 条记忆原样保留。
- 旧 `/api/personas` 保留，不删除数据和接口；新 UI 不再调用它创建人格。
- 云宝使用独立 `/api/yunbao`，不复用旧“多个人格”选择逻辑。

### 7.3 服务端

- `GET /api/yunbao`：所有已登录用户；返回 `can_edit`。
- `PATCH /api/yunbao`：仅所有者；普通用户 403。
- `POST /api/yunbao/state`：所有已登录用户；只改 `active_state`，不改身份/配置。
- `DELETE /api/yunbao`：不开放；云宝不可被删除。
- 会话/记忆接口按 `persona_id=云宝` 查询；写/删记忆仅所有者。

    {"key": "...", "label": "...", "description": "...", "prompt_hint": "..."}

- 三个状态共享同一 `personal_personas.id`。

- 状态选择只出现在云宝对话框；不出现在人格编辑页。

- 切换后下一条消息携带状态；历史消息保留原状态标记。
- 发送仍走全局助手接口，保留页面上下文、表单操作、导航动作。
- 服务端把云宝人格提示词、当前状态、记忆合并进系统提示；返回动作白名单不变。
- 会话入库为云宝线程；前端不再按 `product` 拆分云宝会话缓存。
