# T098 人物运行态与成长

## 1. 问题

人物种子编辑器原本只有一层数据：02–05 的五引擎、防御机制、现实条件、思想钢印一旦填写，
后续 06 生命经历只做记录，无法反馈到人物当前状态。结果人物会永远停留在“出生设定”，
时间线越写越长，人物却没有真正发生变化。

## 2. 两层模型

### 种子层（Seed）

种子是人物长期稳定的底色，包含：

- 01 基础档案
- 02 人格动力结构（长期倾向）
- 03 人格运行与防御机制（默认防御方式）
- 04 现实承载条件（初始环境）
- 05 个体特征与思想钢印（长期原则）
- 06 生命经历与历史沉积（经历、认知、归因、反应、沉积）
- 07 人物初始状态（进入模拟时的快照）

种子层回答：“这个人原本是谁、从哪里来、长期倾向是什么。”

### 运行态层（Runtime）

运行态是人物在当前时间点的版本，包含：

- 02–05 的当前值（不是覆盖种子，而是另一份快照）
- `main_color` 主色调（V/O/D/E/T）
- 成长日志 `growth_log`
- 版本号 `version`
- 最近校准时间 `updated_at`

运行态回答：“经历这些事情之后，这个人现在变成了什么样。”

种子与运行态分离，因此可以保留主色调，同时允许其他引擎随情境升降、防御方式改变、
现实条件变化、思想钢印松动或加固。主色调不是唯一引擎，而是长期底色。

## 3. 事件如何进入人物

事件本身不直接改写人物。进入运行态的链路是：

```
05 世界事件
  → 06 人物生命经历
    → 人物对事件的认知 / 意义判断 / 归因对象 / 情绪反应 / 行为反应
      → 长期沉积（防御倾向、关系模型、风险判断、核心信念…）
        → 作者在 08 运行态与成长中确认“当前值”
          → 写入成长日志 + state_histories
```

这样处理的原因是：同一事件对不同人物意味着不同东西。人物如何解释事件、把原因归给谁、
是否认为自己有控制力，决定了事件会不会改变他，以及改变哪一层。

## 4. 接口

### `GET /api/characters/{id}/runtime`

返回：

```json
{
  "character_id": "...",
  "seed": {
    "engines": {},
    "defense_mechanisms": {},
    "reality_conditions": {},
    "thought_imprints": {}
  },
  "runtime": {
    "engines": {},
    "defense_mechanisms": {},
    "reality_conditions": {},
    "thought_imprints": {},
    "main_color": "O",
    "version": 2,
    "updated_at": "...",
    "growth_log": []
  }
}
```

没有运行态时，runtime 自动继承种子，版本为 0。

### `PUT /api/characters/{id}/runtime`

请求体：

```json
{
  "engines": {},
  "defense_mechanisms": {},
  "reality_conditions": {},
  "thought_imprints": {},
  "main_color": "O",
  "reason": "人物如何理解与归因这次经历",
  "source_event_ids": ["..."],
  "life_history": {}
}
```

行为：

- 只更新运行态，不覆盖种子。
- 只有实际发生变化时才新增成长日志。
- 五引擎变化写入 `state_histories`，字段形如
  `runtime.engines.ovtde.O.val`、`runtime.main_color`。
- `life_history` 是种子与运行态共享的记录层，允许在运行态里补记 06 经历。
- `source_event_ids` 关联具体生命经历，便于回溯“这次成长来自哪些事”。

## 草稿入库撤销与去向提示

AI 解析出的素材在入库前必须先说明去向：

| 草稿类型 | 入库目标 | 结构位置 |
| --- | --- | --- |
| character | 人物库 | 03 人物管理 / 人物档案；同时挂到世界结构·人物与群体 |
| location | 地点库 | 世界结构 / 地理与地点 |
| event | 事件库 | 05 事件管理 |
| organization | 组织库 | 世界结构 / 组织与制度 |
| relationship | 关系库 | 04 关系与组织 |

- 草稿卡片显示“入库去向”，单个入库按钮显示“入库到人物库/地点库…”。
- 批量入库前弹窗按目标库汇总数量。
- 已入库草稿提供“撤销入库”：`POST /api/drafts/{id}/undo`。
- 撤销会删除该草稿刚创建的实体和世界结构挂载节点，草稿退回 `pending`；若实体已被其他关系/事件引用，返回 409 并提示先清理引用，不会静默删除。
- 世界结构“创作草稿”默认显示全部状态，已入库草稿也能直接撤销。
- 08 写作工作台本章草稿同样提供“撤销入库”。

## 07 / 08 作者预设

07 模拟运行和 08 从推演生成章节都提供：

- **作者预设推演方向**：约束世界线与剧情走向，但不得违背人物引擎与既有关系。
- **推演视角**：第一人称、第三人称限知、全知、群像等，决定重点观察谁，不改变客观事件事实。
- 两处设置写入 `localStorage`，自动记住；07 点击“写成章节 →”会把当前方向和视角带到 08。
- 07 的每次推演把方向和视角写入 `simulation_runs.direction / perspective`，历史结果旁可回看。
- 08 生成请求增加 `perspective`，与 `user_direction` 一起进入生成提示词。
- 数据库迁移 `M013` 增加 `simulation_runs.direction / perspective`。

## 访客自带 AI Key

公开部署不能让所有访客消耗站长额度，已增加请求级 Key：

- 顶栏“AI 接入”打开设置，填写 API Key、Base URL、模型。
- 配置只保存在访客浏览器，AI 请求通过以下请求头传递：
  - `X-AI-API-Key`
  - `X-AI-Base-URL`
  - `X-AI-Model`
- 服务端用 `contextvars` 按请求隔离，不写数据库、不写日志；不同访客不会串用客户端。
- 站长共享 Key 由 `AI_SERVER_KEY_ENABLED` 控制；公开部署设为 `false`，`render.yaml` 已默认关闭。
- 只有 AI 相关端点会携带 Key：`/api/ai/status`、`/api/simulate`、`/api/writing/*`、`/api/writings/{id}/analyze`。
- 自定义 Base URL 只允许公网 HTTPS，阻止 localhost 和内网地址。

## 人物删除修复

人物入库时会自动创建“人物与群体”目录节点。删除人物时，该节点此前被当作外部引用，导致 409：

> 人物仍被引用：目录节点（xxx）

现在删除人物会先移除自身挂载节点，再检查关系、事件、任职等真实外部引用。
已用 6 条错误 AI 人物（丹房的味、修士忽然、认得就、修士没再、指着那、身后那）验证删除成功。
