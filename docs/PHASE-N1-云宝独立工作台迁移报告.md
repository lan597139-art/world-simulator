## 1. 最终结构

云宝不再属于 AI 伴侣产品的「个人 AI 人格」模块，而是首页全局侧边栏底部的独立工作台：

```text
首页侧边栏
  ├─ 四大创作产品
  ├─ 用户与身份中心 / 内容社区 / AI 互动中心 / 游戏体验中心 / 内容商城
  └─ 云宝工作台   ← 主导航底部，开发者入口
       └─ 云宝领域（共享工作空间）
            ├─ 世界总览 / 世界管理 / 世界建设 / 世界结构 / 世界设定
            ├─ 人物管理 / 关系与组织 / AI 角色聊天 / 事件管理
            ├─ 时间线 / 模拟运行 / 故事线 / 多路径 / 写作
            ├─ 日记与传记 / 云宝人格编辑器
            ├─ 人物种子编辑器（01–08 完整深层结构）
            └─ 记忆 / 人格运行 / 信息来源 / 时光机 / 归档 / 回收站
```

云宝产品首页为 `yunbao`，工作空间名为「云宝领域」，归属固定为系统所有者 `local`。云宝工作台是开发者私有工作台：侧栏入口只对所有者显示，工作空间与云宝领域的读取也只对所有者开放。

---

## 2. 产品与权限

### 2.1 新独立产品

- 产品键：`yunbao`
- 首页：`yunbao`
- 自动工作空间：开启
- 工作空间名：`云宝领域`
- 允许模块：游戏、文学、日记与传记的全部专业能力，外加云宝人格、记忆与人格运行。

### 2.2 从 AI 伴侣迁出

- `companion` 侧栏不再出现「云宝人格」「记忆管理」「人格运行」。
- `companion` 首页从 `personas` 改为人物管理。
- AI 互动中心的 AI 伴侣区域不再展示云宝入口。
- 伴侣聊天页移除「管理个人 AI 人格」按钮。
- 保留 `companion` 旧人格/记忆/人格运行 API 的读取兼容，避免历史数据无法访问；这些模块不出现在伴侣导航中。

### 2.3 编辑与访问权限

只有 `兰哆哆`（`is_owner=true`）可以进入并编辑云宝工作台：

- `PATCH /api/yunbao`：仅所有者
- `POST /api/yunbao/state`：仅所有者
- `GET /api/products/yunbao/workspace` 与 `POST .../workspace`：非所有者返回 `403`
- `GET /api/yunbao/seed-character`：非所有者返回 `403`
- 云宝领域世界：不出现在非所有者的世界列表，直接读取返回 `403`
- 首页侧栏「云宝工作台」：非所有者不渲染；直接访问 URL 会退回首页
- 工作台内所有非 GET 请求：非所有者携带 `X-Yunbao-Workspace: 1` 时由后端返回 `403`
- 云宝摘要 API 保留只读兼容响应，但不再作为工作台入口；世界、人物、日记等具体内容不对非所有者开放

### 2.4 完整人物种子编辑器

人格编辑器提供两层：

- **人格摘要**：身份、自我描述、自传、表达、互动、记忆策略与成长经历。
- **完整人物种子**：复用人物种子编辑器的 01–08 深层结构，包括基础档案、人格动力结构、人格运行与防御机制、现实承载条件、个体特征与思想钢印、生命经历与历史沉积、初始状态、运行态与成长。

实现方式：云宝仍是唯一 `PersonalPersona`，`seed_character_id` 只指向「云宝领域」中的承载人物；不创建第二个人格身份。迁移 `M042` 增加该绑定字段。后续 `M043`（设置中心）、`M044`（社区社交）在不改动云宝数据的前提下扩展账号与社区表。点击「人物种子编辑器」或人格编辑器里的「打开完整人物种子编辑器」即可进入。

云宝 AI 的提示词现在同时包含：人格摘要、完整人物种子、云宝领域的世界背景、人物、关系与事件。这样云宝回答时知道这些人格、经历与世界是她自己的，而不是普通 AI 的装饰性设定。

## 5. 运行要求

1. 重启后端，加载五产品矩阵、`/api/products/yunbao/workspace` 与只读拦截。
2. 刷新前端。
3. 保持 `兰哆哆` 登录，从首页侧边栏底部进入「云宝工作台」。
4. 直接访问：

```text
/?product=yunbao&page=yunbao
```

### 5.1 本次「开发者仍只读 / Not Found」的原因

不是账号权限配置错误，也不是需要关闭鉴权：

1. 8000 端口运行的是旧后端：产品矩阵仍为四产品，`/api/yunbao` 与 `/api/products/yunbao/workspace` 返回 404。
2. 前端 `ws.authUser` 缓存来自旧版 `/api/auth/status`，没有 `is_owner` 字段，导致已登录的 `兰哆哆` 被误判为访客并显示只读横幅。
3. 重启后端后，`AuthGate` 会用最新 `/api/auth/status` 刷新缓存用户，不再需要退出重登。

如再次出现四产品矩阵或 `/api/products/yunbao/workspace` 404，先确认 8000 端口进程已重启到当前代码，而不是修改权限或绕过登录。
