## 2. BMOS（运行时工程层）

### 2.1 接口关系（BMOS §0.1–0.3）
- BMOS 是构建在 ESA 母核（L0–L7 + L∞）上的运行时，工程对象是底层状态，变量严格映射母核层级。
- **动力源外置**：O/V/D/E/T 五维 Need 与沙盒 N1–N6 由外部「沙盒探测测试」注入；BMOS 只负责状态调度与输出，不定义心理标签。
- 四项核心合同：①动力源合同（外置路由 → L3 策略 → L4 动作；禁止道德语义进入路由，违者降级 MIN_ACTION 并记 `NEED_SMUGGLING`）；②状态机合同（工况必须对应 L0–L7，禁止自创状态术语）；③反噬控制合同（L∞ 动作链：止模 → 降载 → 落地 → 回写仅记状态）；④数据沉积合同（L4 输出默认不得改写 L5，须经 L6 PASS；旁路/降级冻结写回）。
- 反向因果声明：一次输出不得定型人格，反复输出须经 L6 审计才可进入 L5。
- 代码现状：❌ 无 Need Vector、无 L3 路由、无 L∞、无 L6 审计。

### 2.2 L0–L7 状态机映射（BMOS §2.3、§7.1）
- 状态机三态九档：稳定态 S0 巡航 / S1 优化 / S2 低带宽；失调态 D0 摩擦积累 / D1 目标漂移 / D2 解释过载；退相干态 Dec0 旁路生存 / Dec1 熔断保护 / Dec2 止模态。
- 转移原则：硬边界优先（E/Integrity/Pain/内耗）；位移优先于解释；进入 D/Dec 态时写回必须收缩或冻结。
- `Event-Blank Slot`：带宽不足时写入占位记录（时间戳/触发器/状态变更/写回冻结标记），防止强行补叙事造成污染。
- §7.1 模块映射：L0–L2 → 内核物理层+状态机；L3 → 路径选择+交互协议；L4 → 动作输出+关系叙事包；L5–L6 → 记忆写入+主权裁决。
- 代码现状：❌ 无状态机。`runtime_state.main_color/version` 是展示标签，**不等于** S/D/Dec 工况，不得混称。

### 2.3 Need Vector（BMOS §3.1）
- `N = (N_O, N_V, N_D, N_E, N_T)`，五维并列稳态代价权重；不要求同时满足，不作道德判决。
- 工程约束：Need 是 L3 路由输入；不得越权写回 L5。
- 代码现状：🟡 `characters.engines`（O/V/D/E/T 0–100）+ `dominance` 是静态权重与主导标签；无"当前轮值主导 Need + 强度"的运行时字段。

### 2.4 轮值 / 代偿 / 冲突干涉（BMOS §3.2）
- **轮值**：主导 Need 随三个信号切换——外界扰动谱、内部预算（L1 能量/L2 硬件/L3 内耗/负载）、L5 沉积偏置。
- **代偿**：某一维长期被压制 → 张力累积 → 以更高幅度/更低阈值回归（五种典型样式，逐维给出）。
- **冲突干涉**：多维强激活且方向不一致 → 分支膨胀/解释增加/位移下降 → L3 内耗上升；处理原则"先保带宽，再求整合"。
- 明确给出的规则：`Dominant = argmax(N_i)`；冲突高时可 Top-2/Top-3 并列但必须缩分支。
- 代码现状：❌ 无轮值/代偿/冲突逻辑。可先落地"主导 = argmax(engines)"标签（现有 `dominance` 已近似），代偿/冲突需参数化配置。
- ⚠️ 待确认：五维权重数值、轮值时间窗、代偿阈值与幅度、冲突判定的量化标准。

### 2.5 L3 调度与行为路由（BMOS §3.3）
- 路由输入：`N`、`Mode ∈ {L, H}`（由 L1 势能决定）、`Budget`（能量/硬件/内耗/痛觉/负载分档）、`L5_Bias`。
- 路由输出：行为向量 `B {direction, priority, bandwidth, risk_cap}`——是"候选与权重"，不是最终动作。
- **方向与供能解耦**：Need 决定方向，L1 预算决定幅度；低能时方向保持、幅度收缩。
- 风险封顶：L2 痛觉高或完整度低 → 风险上限下降。
- 代码现状：❌ 未实现。推演 prompt 中的 engines 只是数值文本，无 Mode/带宽/风险上限语义。

### 2.6 L5 记忆沉积（BMOS §2.4、§6.x）
- **地质模型四层**：L5-F 浮动层（短期易挥发）/ L5-S 脚本层（动作模板，最易被污染固化）/ L5-D 沉积层（长期偏置与吸引子，承重最高）/ L5-M 元信息层（来源/触发器/门槛/失真标记/回滚指针）。
- 写入三步：摘要化 → 门槛判定 → 压缩编码；读取须带索引与预算（Read Budget）；另有去毒（Detox）、回滚（Rollback）、冷启动（Cold Start）协议。
- 污染与回滚三机制：写回门槛、失真标记 `distortion_meta`、回滚指针。
- 代码现状：🟡 `life_history.events` 是"完整叙事追加"，与理论"压缩沉积+门槛"方向相反，最多只能视为 **L5-S 雏形**；无 L5-F/S/D/M 分层、无失真标记、无回滚指针。`state_histories` 是字段级审计，与记忆沉积不是同一对象。

### 2.7 硬件配置与人格配置（BMOS Part IV）
- `HW-P` 硬件配置：敏感度 / 恢复率 / 代谢衰减 / 残余驱动偏置 + `Black_Box_Reserve`（不可解释核），解释"同一协议跑出不同稳定态"。
- `P-P` 人格配置：偏好 / 厌恶 / 奖励曲线 / 稳定吸引子，软参数，不改闭环。
- `Cross-Profile` 不变量：硬边界（不可调）/ 可调区 / 保留残差。
- 代码现状：🟡 `runtime_state` + `defense_mechanisms` + `thought_imprints` 是软参数雏形；无 HW-P/P-P 分层、无硬边界清单。
- **强对应**：WEP-C 的 `C_profile` 参数字典（见 §4.1）可直接充当 P-P 的具体实现。

### 2.8 熔断、降频与反噬（BMOS §2.2、Part III）
- 代价函数 `J(a)`：输入 E(t)/Integrity/Pain/内耗/Load + Need 权重 + L5 偏置；**前提 Goal=SET**，否则不可定义。
- 慢路径允许/禁止条件；L∞ 旁路触发条件与输出合同；降频触发与效果；熔断触发与合同。
- 反噬控制：叙事税、解释污染（惯性/二极管化/偏置写回）、元认知摩擦链路（建模↑ → 冲突↑ → 降频 → 位移↓）。
- 代码现状：❌ 未实现；无 E(t)/Integrity/Pain/内耗字段，无 Goal 状态。

### 2.9 分支隔离含义（由 BMOS 机制推导）
- 按分支必须隔离的运行时状态：Need 当前值、Mode(L/H)、S/D/Dec 工况、E(t)/Integrity/Pain/内耗/Load、L5 四层记忆与失真元信息、熔断/降频计数、J(a) 地形（L5 偏置）。
- 记忆回滚对分支的意义：理论要求"回滚指针 + 失真标记 + 可审计原因"；分支节点快照提供系统级回滚点，节点表应补 `rollback_reason` 字段。
- ⚠️ 理论**未定义**多分支并存时的隔离规则 → 由代码侧设计（阶段 C §5），不冒充理论。

## 4. WEP 分册 C/D/E（人格谱系 / 存在体验 / 叙事渲染）

### 4.1 C 人格谱系参数（可实施性最高）

- **C.1 基础阈值**：六组共 24 个阈值，全部 `[0.0, 1.0]`，且给出 JSON 数值示例——威胁防御 7 阈值（fear/fight/flight/freeze/fawn/ally/dissociation）、羞耻体面 4、地位嫉妒 3、连结依恋 4、冲动克制 3、热崩递归 3。
- **判定规则明确**：遭遇压力时比对 7 个防御阈值，"哪个数值最低，优先执行哪个动作"；`dissociation_threshold` 被突破则强制挂起 L2 痛觉与 L3 慢路径，只保留最低限度 L4 动作。
- **C.2 调节风格**（热处理/反刍/恢复/冲突调节/叙事防御）；**C.3 策略取向**（时间偏好/资源策略/互惠/忠诚背叛/欺骗/风险）；**C.4 关系风格**（依恋取向/信任背叛/边界亲密/控制勒索/修复断裂）；**C.5 自我修辞**（密度节奏/直白含蓄/解释风格/立场边界/攻击讽刺/真话策略/场景门控）；**C.6 成长曲线**（6 能力域 × 6 属性/训练成本/环境连续谱/退化）；**C.7 全量 JSON DNA + 三大预设**（自立型/依附型/野心权谋型）+ System Prompt 模板。
- 代码现状：🟡 `basic_profile`、`defense_mechanisms`、`thought_imprints` 有相近概念，**无 C_profile 参数体系**。
- 关键差异：C 是"给定数值"的参数字典（非待确认公式），可直接作为人物种子扩展落地；但新增字段须遵守任务书约束 3（不得删除/合并既有字段分类）。
- 与 ESA/BMOS 关系：C 的阈值 = BMOS §7.4 调制层"阈值偏置"的具体化；C 的策略/关系/修辞 = `P-P` 软参数的具体字典。

- **D.2 中间态**：五维仪表盘 E/T/B/V/A（V 效价 -1~1）；12 类可累加负载——6 负项（fatigue/shame/debt/grief/rage/isolation）与 6 正项（ease/pride/trust/gratitude/courage/belonging）；更新逻辑（压强→三态→V/A；事件结算→负载升降；时间衰减，**禁止无代价清零**）。

- **D.5 暗雷系统**：IMMEDIATE / DELAYED / LOGGED_ONLY 三分布；松懈窗口引爆；暗账四把刀（概率/可见性/权限/关系调制）；后台事件对象字段（Event_ID、Severity、Distribution、Trigger_Window、Slack_Window_Hit、Non_Manifest_Effect）。
- **D.6 亲密摩擦层**：四大摩擦因子 → 五大摩擦输出。

- 定位：**纯表达/渲染层**，理论明确"渲染函数只负责输出，不许调用状态更新"。
- 代码现状：🟡 `writing.py` 直接流式渲染，无 PAL/禁词闸门/状态预算；写作页有零散约束但未系统化。
- 对多路径推演接入：多路径推演只需保证结局/快照数据满足 E 的"输入包"字段，不要求 E 参与计算；结局叙述生成可作为阶段 E 的可选增强。

### 4.4 四者关系（完整链路）

```
WEP-A（世界参数/六轴计算）
   → WEP-D（个体体验转译：五维+负载）
   → WEP-C（个体阈值与策略：C_profile）
   → BMOS（L3 路由/状态机/输出限制）
   → L4 行动（事件与关系变化）
   → WEP-E（渲染输出，只读）
ESA 为母核层级与状态语言；BMOS 为运行时；C/D/E 为其参数与表达分册。
```

### 4.5 待确认（C/D/E）

2. D 六轴由 A 计算的具体映射公式未给出；12 负载的衰减速率与结算权重未给出。

## 5. 映射结论（对多路径推演的直接影响）

1. **理论层完整、运行时层几乎空白**：ESA 定义了完整层级与状态语言，BMOS 定义了工程机制，但代码只实现了"静态种子 + 运行态标签 + 履历追加"。多路径推演必须建立在"快照 + 标签 + 文本"的现实能力上，不能假装有 BMOS 状态机（如 S/D/Dec 工况、Need Vector、熔断）。
2. **最小理论闭环已具备**：事件认知表（`character_event_perceptions`）字段与理论"事件认知"高度一致，接入推演 prompt 即可实现"同一事件不同人物不同反应"的最小闭环。
3. **可直接落地 vs 需待确认**：WEP-C 的参数是**给定数值**（阈值 JSON、三大预设），可直接实现；BMOS 的轮值/代偿/阈值、WEP-A 的六轴映射公式、D 的负载速率均**未给数值** → 一律"可配置接口 + 待确认"，默认 no-op。
4. **六轴是统一入口**：A.5/D.1 同名六轴 + negentropy 是"世界条件影响人物行为"的唯一理论通道，分支快照必须包含其当前值。
5. **E 不进入计算**：渲染层只消费数据、不写状态；分支/结局数据须满足其输入包字段即可。
