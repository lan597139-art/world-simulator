# PHASE L1：05 多剧情事件整合与故事线重做实施报告

日期：2026-11-11  
范围：产品入口、05 事件管理、故事线管理、相关 API 与回归测试

## 1. 结论

本轮按整改报告重做了两处产品功能，而不是修改文案、颜色或导航名称：

1. **取消“多路径推演”的独立产品入口**，把多路径能力并入 05 事件管理；后端分支/沙盒接口与既有数据保留。
2. **把 05 事件从“单一事件表单”改为“事件基础信息 + 事件发展与选择”**：选择、结果、后续事件是三个独立对象；支持编辑、删除、排序结果分支、现场新建后续事件、递归查看完整发展关系、按需生成/进入平行沙盒。
3. **把故事线管理从技术配置页重做为可视化故事树**：左侧 05 事件库、中间故事线画布、右侧详情/连线检查器；支持拖入事件、跨线移动、排序、创建/编辑/删除故事线、建立事件级叙事连线。

状态口径：

- 代码实现：已完成。
- 自动化回归：通过（后端 422 项 / 17 套件，迁移演练 28/28、64 表；前端 `tsc`、`vite build` 通过）。
- 浏览器验证：已完成两条主流程（临时世界，验证后删除）。
- 生产环境：未部署验证；本轮只验证本地运行。

## 2. 产品入口调整

### 2.1 已移除的入口

- 左侧导航中的“多路径推演”独立项已移除。
- 07 模拟运行页底部的“前往多路径工作台”入口已移除。

### 2.2 保留的能力

- `MultiPathPage` 路由仍保留，但不再作为独立产品入口展示。
- 05 事件页顶部提供“分支沙盒 · 多路径能力”按钮，可进入既有分支工作台。
- 选择结果生成沙盒后，结果行显示“进入沙盒”，直接打开对应分支。
- 后端 `multipath`、`SimulationBranch`、分支树/方向/结局接口、既有分支数据均未删除。

这样多路径的“产品归属”在 05，技术上仍复用原引擎，没有新建第二套分支系统。

## 3. 05 事件管理

### 3.1 基础字段完整保留

创建/编辑事件仍包含并保存：

- 事件名称
- 小说内时间
- 剧情线
- 事件层级（宏观/中观/微观）
- 事件领域（多选）
- 事件极性
- 事件强度
- 发生地点
- 涉及组织
- 参与人物（多选）
- 因果关联事件（多选）
- 客观事实描述

新增的“事件发展与选择”不替换上述字段，只作为事件保存后的扩展区域。

### 3.2 选择、结果、后续事件分离

数据与界面均按三层表达：

| 概念 | 数据对象 | 界面 |
| --- | --- | --- |
| 选择 | `EventChoice` | “是否揭发 / 暗中调查”等决策点，独立标题与说明 |
| 结果 | `EventChoiceOption` | 每个选择下的分支选项，独立“结果说明” |
| 后续事件 | `Event`（通过 `outcome_event_id` 引用） | 从 05 事件库选择，或现场新建后关联 |

- 一个事件可以有多个选择。
- 一个选择可以有多个结果分支。
- 一个结果可以关联一个已有后续事件，也可以现场新建后续事件。
- 后续事件本身仍可继续添加选择，形成递归多剧情，而不是把全部内容塞进一个文本框。

### 3.3 已实现的编辑操作

- 添加选择、页内编辑选择标题/说明、删除选择、选择点上移/下移（`order_index` 持久化）。
- 添加结果、页内编辑结果文案/结果说明/后续事件绑定、删除结果。
- 结果分支上移/下移（`order_index` 持久化）。
- 结果绑定已有后续事件，或“+ 新建后续事件 → 创建并关联”。
- “生成平行沙盒”；已有沙盒时显示“进入沙盒”。
- “发展关系预览”和“查看完整发展关系”：沿 `outcome_event_id` 递归读取后续事件的选择，带循环保护和深度上限。
- 事件创建成功后停留在当前页并自动进入编辑态，立即出现选择编辑区；未保存时显示明确的占位说明，不伪造选择。

### 3.4 当前边界

- 选择点与结果分支均已持久化排序；当前使用上移/下移按钮，不是拖拽排序。
- 选择/结果编辑为页内表单；没有新增独立弹窗组件。

## 4. 故事线管理重做

### 4.1 三栏结构

- **左栏：事件库**
  - 数据来自 `/api/events?world_id=...`，即 05 事件，不复制事件。
  - 支持按名称/描述搜索。
  - 支持按人物、剧情线、事件层级过滤。
  - 事件卡可拖入中间画布。

- **中栏：故事树画布**
  - 每条故事线是一列，事件卡按顺序纵向排列。
  - 支持主线、支线、副本、暗线/影线、群像五类线。
  - 故事线可绑定人物，形成人物线。
  - 支持创建、改名、改类型、改绑定人物、删除、左右调整线顺序。
  - 事件可从事件库拖入，也可在故事树内拖动到其他线或调整顺序；同时保留上移/下移按钮。
  - 同一事件可以被多条线引用，删除线或移出线不会删除 05 事件。
  - 顶部“连线”进入连线模式：依次点击起点/目标事件，建立事件级叙事关系；同一条线内的两个不同事件也允许连线。
  - 连线以 SVG 曲线绘制，右侧列出连线并提供删除。

- **右栏：详情/检查器**
  - 选中事件时显示事件信息、所属线、人物、到 05 编辑、移出故事树。
  - 选中故事线时显示线信息、编辑、删除。
  - 显示叙事连线列表与错误/操作日志。

### 4.2 数据兼容

- 使用既有 `story_threads`、`story_thread_events`、`story_thread_edges`，没有新建平行数据模型。
- 旧的 `story_spaces / story_units / story_choices / story_endings` 数据与接口保留，未删除、未改写。
- 新故事树为空时提供“从既有故事导入”：把既有结构单元映射为故事线，把单元事件引用为树事件；事件仍是 05 引用，不复制事件。该操作幂等（同标题线复用、同事件不重复挂接），需用户确认后执行。
- 旧版技术化“空间/结构单元/选择节点”界面不再作为故事线主界面出现。

### 4.3 布局边界

- 当前画布是“分栏 + 自动纵向布局”，不是自由坐标画布；拖动用于入线、跨线和排序，不保存任意 X/Y 坐标。
- 连线锚点按事件卡位置计算，因此连线主要表达“叙事关系”，不是手工绘制的任意曲线。

## 5. 后端/API 变更

| 变更 | 文件 | 说明 |
| --- | --- | --- |
| 事件关联移动/排序 | `backend/story_threads.py` | `PATCH /api/story-thread-events/{id}` 支持 `thread_id / order_index / role / note`，移动时重排目标线 |
| 人物线与父线编辑 | `backend/story_threads.py` | `PATCH /api/story-threads/{id}` 支持 `character_id / parent_thread_id / order_index`，含父子环检测 |
| 事件级连线校验 | `backend/story_threads.py` | `POST /api/stories/{id}/thread-edges` 校验事件属于该世界且已挂对应线；同线允许连接两个不同事件 |
| 连线返回事件名 | `backend/story_threads.py` | 边返回 `from_event_name / to_event_name`，便于检查器展示 |
| 结果分支排序 | `backend/event_choices.py` | `PATCH /api/event-choice-options/{id}` 支持 `order_index` 并重排同选择下结果 |
| 选择点排序 | `backend/event_choices.py`、`backend/models.py` | `EventChoice.order_index`；`PATCH /api/event-choices/{id}` 支持排序，创建/删除时重排同事件选择 |
| 选择排序迁移 | `backend/migrations/m028_event_choice_order.py` | 新列 + 按创建时间回填既有选择 |

未删除任何既有后端路由或表；迁移为 M001–M028。
