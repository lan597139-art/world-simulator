# T097 双轨写作工作台

## 一、目标

08 写作辅助从“推演正文生成器”升级为双轨创作工作台：

- **架构师模式**：先有世界树/人物/事件/推演，再让 AI 在既定规则下生成章节，作者精修。
- **探险家模式**：不填前置表格，新建空白章节直接写，写完后解析本章，把素材以草稿形式收回世界树。
- 两种模式共用同一套章节库、富文本编辑器、草稿箱与世界设定。

## 二、界面结构

### 1. 入口

进入任意世界 → 08 写作辅助：

- 没有章节时显示两张入口卡：“架构师模式（从推演生成）”和“探险家模式（新建空白章节）”。
- 左侧手稿库始终可新建空白章节；每章带“架构师/探险家”徽标、字数、更新时间。
- 07 模拟运行右侧结果区新增“写成章节 →”，点击后跳到 08 并自动勾选该事件。

### 2. 编辑器

- Tiptap 富文本：标题 2/3、粗体、斜体、删除线、引用、有序/无序列表、撤销/重做。
- **自动防抖保存**：停止输入约 800ms 后 `PATCH /api/writings/{id}`，不需要保存按钮。
- 字数、保存状态（已自动保存/未保存/保存中/保存失败）显示在标题下方和底栏。
- 旧版纯文本章节读取时会自动转成段落 HTML。

### 3. 双轨侧边栏

- **推演参照**：架构师章节显示绑定事件的描述、时间、极性与最近一次推演的世界变化/人物行动；没有推演时提示去 07。
- **素材提取**：探险家章节显示“一键提取设定”和本章草稿列表；两种模式都可切到此页。
- 划词悬浮菜单：
  - 设定向：提取为人物 / 地点 / 事件。
  - 创作向：AI 润色 / AI 扩写 / 生成对白。
- 提取/入库操作会即时刷新侧栏草稿；入库成功后提示去世界结构细化。

### 4. 草稿箱（世界树内）

世界结构新增第九个分支“创作草稿”：

- 待入库 / 全部筛选。
- 展示名称、类型、置信度、摘要、原文证据、来源章节。
- “入库”才创建正式实体；此前只存在 `entity_drafts`，不会污染正式设定。
- 入库后：
  - 人物：创建人物档案（五引擎/机制/沙盒保持空白，等待补全），并自动挂到“人物与群体”目录。
  - 地点：进入地理树，`status=draft`。
  - 事件：进入事件列表，`event_status=draft`。
  - 组织：进入组织结构，`status=draft`。
  - 关系：仅当两端人物已存在时才允许入库。

## 三、后端

### 1. 数据模型（M011）

`stories` 新增：

| 列 | 用途 |
|---|---|
| `title` | 章节标题 |
| `plain_text` | 纯文本缓存（字数、导出、解析） |
| `word_count` | 字数 |
| `mode` | architect / explorer |
| `status` | draft / published |
| `source_event_ids` | 架构师章节绑定的推演事件 |
| `source_simulation_ids` | 预留 |
| `updated_at` | 手稿库排序 |

新增 `entity_drafts`：

| 列 | 用途 |
|---|---|
| `entity_type` | character/location/event/organization/relationship |
| `name` / `summary` | 展示 |
| `payload` | AI 或规则抽取的字段 |
| `evidence` | 原文证据 |
| `confidence` | 0–1 |
| `status` | pending/accepted/ignored |
| `story_id` | 来源章节 |

迁移：`backend/migrations/m011_writing_workspace.py`。

### 2. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/writings?world_id=` | 章节列表 |
| POST | `/api/writings` | 新建空白/生成章节 |
| GET/PATCH/DELETE | `/api/writings/{id}` | 读取/自动保存/删除 |
| POST | `/api/writing/generate` | 流式生成推演正文 |
| POST | `/api/writings/{id}/analyze` | 解析整章或选区，返回草稿 |
| POST | `/api/writing/extract` | 选区提取兼容入口 |
| GET | `/api/writings/{id}/drafts` | 本章草稿 |
| GET | `/api/worlds/{id}/drafts` | 世界草稿箱 |
| PATCH | `/api/drafts/{id}` | 改草稿字段/状态 |
| POST | `/api/drafts/{id}/approve` | 入库为草稿实体 |
| POST | `/api/drafts/{id}/ignore` | 忽略 |
| POST | `/api/writing/assist` | 流式润色/扩写/对白 |

### 3. 抽取策略

1. 优先调用 DeepSeek JSON 抽取（人物/地点/事件/关系/组织）。
2. AI 不可用（未配置、额度不足、网络失败）时自动降级为规则抽取：
   - 人物：对白前后的说话人；
   - 地点：来到/进入/抵达/站在等后的场所；
   - 事件：本章首句作为标题，正文摘要；
   - 组织：门/宗/派/阁/殿/帮/会/盟/谷/府/族/家后缀。
3. 已存在的同名正式实体与待处理草稿会自动跳过，避免重复入库。

## 五、当前限制

- AI 通过 OpenAI 兼容接口调用，`backend/.env` 可配置 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。当前使用硅基流动：`https://api.siliconflow.cn/v1` + `deepseek-ai/DeepSeek-V4.1-Flash`：
  - 解析本章仍可用（规则抽取降级）；
  - AI 生成/润色/扩写/对白会返回明确的“AI 额度不足”提示，不会写入空章节。
- 入库人物只带基础档案，五引擎/九层机制/沙盒需要作者后续在人物种子编辑器补齐，这是“草稿待细化”的设计意图。
