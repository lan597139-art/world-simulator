## 一、调整后的一级、二级、三级导航树

### 1.1 一级结构（3 个业务区域 + 2 个工具入口）

```
世界模拟器
├── 一、创作与体验
│   ├── 创作中心
│   ├── 内容社区
│   ├── 社区社交
│   └── 消费体验中心 ◀ 新合并入口
│       ├── AI 互动
│       ├── 游戏体验
│       └── 内容商城
├── 二、创作管理
│   ├── 创作者资产库
│   └── 我的作品
├── 三、账户服务
│   ├── 灵果资源
│   └── 商业与服务中心
│
└── 工具入口（不占业务区域）
    ├── 设置中心
    └── 云宝工作台（开发者）
```

**相对现状的 3 个一级变化**：
| # | 变化 | 现状 | 目标 |
|---|---|---|---|
| 1 | **合并消费体验入口** | AI 互动中心 / 游戏体验中心 / 内容商城 = 3 个并列一级 | 消费体验中心 1 个一级，内部 3 分区 |
| 2 | **个人空间组降级** | "个人空间"（用户与身份中心）为独立一级分组 | 移出业务区域，作为顶栏头像菜单 + 账户服务下"身份与资料"二级（**待确认 A1**） |
| 3 | **设置归位** | 侧边栏底部"设置" | 保持工具入口地位（非业务区域），并在个人菜单中同步入口 |

### 1.2 消费体验中心内部结构（需求 1.3 建议结构落地）

```
消费体验中心
├── 首页（分区导航，不承载业务数据）
│   ├── 免费体验 / 需消费项目（服务端规则决定，前端不推断）
│   └── 我的进度与已购（聚合入口）
├── AI 互动
│   ├── AI 角色互动（对话、群聊、角色扮演）
│   └── 其他 AI 体验（伴侣、多人聊天室[待后端]）
├── 游戏体验
│   ├── 互动故事（剧情游戏）
│   ├── 角色扮演
│   ├── 多人体验（待后端，保持空态标注）
│   ├── 已保存游戏 / 进度
│   └── 游戏作品
└── 内容商城
    ├── 商品与资产
    ├── 购买与授权
    ├── 订单
    ├── 创作者店铺
    └── 资产预览
```

**业务边界约束（需求 1.3"注意"条）**：合并的只是**产品入口与消费场景**。AI 互动、游戏体验、内容商城保留各自的数据结构、服务端接口与页面实现；消费体验中心只提供统一外壳（导航 + 分区标题 + 消费提示），**不合并三者的业务模块**。

内容社区

├── 作品（公开作品流 + 阅读器）
├── 世界（世界专区）

├── 剧情（剧情专区）

### 1.4 创作中心（收敛后）

```
创作中心
├── 开始创作（场景入口：游戏 / 文学 / 漫画 / 虚拟角色 / 日记与传记）
├── 最近创作（最近 3 个世界 + 最近 3 部作品，一键继续）
└── 快捷操作（新建世界 / 新建 OC / 新建作品 / 导入素材到资产库）
```
- **8 个专业工具按钮从首页移除**（世界管理/人物/关系/事件/时间线/模拟/故事线/写作）。它们已存在于产品工作区二级导航（`nav_groups`）与资产库目录中，首页不再重复陈列——直接落实需求 1.3"不把所有专业模块同时堆在创作中心总览页"。
- 3 个资产统计卡保留但降级为"最近创作"区的一行摘要，计数口径统一到后端 `getWorkSummary` + 世界/人物统计服务（统一口径方案见 5.3）。

### 1.5 创作管理（两页职责钉死）

```
创作管理
├── 创作者资产库（收纳/组织/发布/回收容器）
│   ├── 全部内容 / 未分类内容
│   ├── 按世界的文件夹树
│   ├── 内容（11 类原子资产：世界/人物/地点/组织/事件/故事/笔记/图片/视频/音频）
│   ├── 已归档
│   └── 回收站
└── 我的作品（项目/作品属性）
    ├── 全部作品（场景筛选：游戏/文学/漫画/虚拟角色/日记与传记）
    ├── 创作中 / 已完成 / 草稿
    └── 作品详情（关联世界、引用人物、进入创作场景、发布）
```
**边界规则**（呼应需求 1.4 约束）：
1. 资产库计数**不得**计入"作品数量"，作品数只来自作品服务；
2. 文件夹只负责组织，移动不改变资产 ID / 世界归属 / 关系；
3. 封面写入资产库需**显式关联 ref**（现状是单向无关联写入，见 5.3）；
4. 两套归档语义统一：资产库"归档"= 资产可见性封存；作品"归档"= 作品状态。**同名不同物必须在文案与图标上区分**（待确认 A6）。

### 1.6 账户服务（目录化，标注可用状态）

```
账户服务
├── 灵果资源
│   ├── 余额与来源分类（来源分类待后端，见待确认 A7）
│   ├── 我的灵植（世界灵植 / OC 灵植）
│   ├── 兑换灵植（灵果 → 灵植）
│   ├── 赠送与打赏
│   ├── 灵果流水
│   └── 奖励领取
└── 商业与服务中心
    ├── 灵石账户与充值（现为沙盒充值，标注"非真实支付"）
    ├── 资源兑换（灵石→灵果/灵植：**待后端与比例确认**）
    ├── 打赏与收益（我的打赏 / 收到的打赏 / 收益明细）
    ├── 提现（**通道未接入，保持禁用空态**）
    ├── 创建资源（OC 创建资源 / 世界创建资源）
    ├── 资源流水（充值/兑换/消费/打赏/创建消耗/赠送/提现）
    └── 其他商业服务（会员 / AI 服务 / 创作者结算）
```
- **两侧互链**（现状零互链）：灵果资源页 ↔ 商业与服务中心，页面顶部各放一条"另一账本"入口与一句关系说明（灵果=虚拟资源，人民币=现金账单，二者不可互换，除规则允许的打赏反向兑换）。
- **站长「经济后台」从灵果资源页抽出**，迁入设置中心的运营区（或独立管理路径），不再作为个人资源页的第 5 个 tab（**待确认 A8**）。

## 六、导航实现方案（工程口径）

### 6.1 导航单一真源（解决 3 份重复定义）

新建 `src/navigation/globalNav.ts`：
```
export interface GlobalNavItem { key: PageKey; label: {zh,en}; icon: LucideIcon; }
export interface GlobalNavGroup { title: {zh,en}; items: GlobalNavItem[] }
export const GLOBAL_NAV: GlobalNavGroup[]   // 唯一真源（含图标）
export const TOOL_ENTRIES = [settingsEntry, yunbaoEntry]
```
- `CreationCenterSidebar` 与 `navRegistry.GLOBAL_NAV_GROUPS`/`buildBreadcrumb` **全部改为消费 `GLOBAL_NAV`**；
- `PageKey` 类型从 App.tsx 内联迁到 `src/navigation/types.ts` 单一定义；
- 侧边栏不再硬编码 `groups()`。

### 6.2 消费体验中心的路由形态（待确认 A2）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A（推荐） | 侧边栏 1 项"消费体验中心"；进去为分区首页；三分区各为独立 page key（`ai-center`/`game-center`/`content-store` 保留），面包屑显示"消费体验中心 > AI 互动 > 当前页" | 不破坏三页实现；面包屑天然三级；返回键清晰 | 需要一处"分组壳" |
| B | 单页内 tab 切换三区 | 实现最省 | 三页合并会破坏业务边界（需求明令禁止方向） |

采用 A：新增 `experience-center` 作为分区首页，三个既有 page key 的**父级**在 navRegistry 中改为"消费体验中心"。

### 6.3 页面可链接化（支撑返回键与分享）

- `?page=<PageKey>` 参数与 `activePage` 双向同步（`replaceState`），页面切换 `pushState`，`popstate` 回放；
- 目标：需求 1.6"保持全局导航、模块导航、面包屑和浏览器返回的职责清楚"；
- 兼容现状 `?product=`；`CommunitySocialPage` 里硬拼的 `window.location.assign('/?page=community#…')` 改为常规导航。
