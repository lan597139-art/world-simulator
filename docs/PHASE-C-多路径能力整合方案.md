# 阶段 C：现有多路径能力整合方案（07 / 08 可选入口）

原则：**不重建多路径引擎，不改 07/08 原有主流程**。多路径作为「可选能力」挂在两个既有页面，默认关闭。

---

## 1. 复用清单（先确认已有能力）

| 能力 | 现有实现 | 复用方式 |
| --- | --- | --- |
| 发展方向 | `simulation_directions` + `/api/events/{id}/directions`（CRUD/复制/禁用/排序/AI 建议） | 07/08 直接调用 |
| 分支创建 | `POST /api/branches`（自动建分叉节点、base/current 快照） | 两处入口共用 |
| 分支推演 | `POST /api/branches/{id}/simulate`（沙盒快照，不污染主线） | 07 开启多路径时使用 |
| 节点回溯 | `POST /api/branches/{id}/rollback` | 故事线空间回溯复用 |
| 结局 | `POST /api/branches/{id}/endings`、`/api/endings/compare` | 故事线结局复用 |
| 对比 | `POST /api/branches/compare` | 空间对比复用 |
| 快照/隔离 | `world_lifecycle.dump_world(..., branch_id)` | 空间状态隔离复用 |
| 应用分支 | `POST /api/branches/{id}/apply`（覆盖 + 备份） | **不在 07/08 默认暴露**，仅在多路径页保留 |

不新建：方向表、分支表、节点表、结局表、快照机制、对比接口。

## 2. 07 模拟运行：可选多路径入口

### 2.1 交互

在 07 现有「开始推演」区域旁增加一个开关（默认关）：

```
[ 启用多路径（可选） ]  ○关  ●开
```

- **关闭**：完全走现有流程，按钮、请求、结果展示不变（`POST /api/simulate`）。
- **开启**：在现有结果区下方展开「多路径面板」（不替换原结果）：
  1. 当前事件的方向列表（可新建、可 AI 建议、可勾选启用）；
  2. 「用该方向创建分支」→ `POST /api/branches`；
  3. 分支列表（本事件下）：可继续推演、回溯、生成结局；
  4. 「前往多路径工作台」链接（保留旧入口）。

### 2.2 数据流

```
选择事件（既有）
  → 关闭：POST /api/simulate            → simulation_runs（主线）
  → 开启：GET  /api/events/{id}/directions
           POST /api/branches
           POST /api/branches/{id}/simulate → simulation_runs(branch_id) + 节点快照
```

关键：开启后**仍可**执行一次主线推演；多路径是并列能力，不是替代。

### 2.3 需要的兼容改动（小）

1. `src/api/config.ts` 的 `needsAiKey` 增加：
   - `/api/branches/`（simulate/rollback/endings/directions suggest）
2. 07 的错误语义统一（A2/A3）。
3. `SimulationPage` 中 `127.0.0.1:8000` 改为 `API_ORIGIN`（A6）。
4. 不新增数据库字段。

## 3. 08 写作辅助：可选多路径创作入口

### 3.1 交互

在 08 生成区增加开关（默认关）：

```
[ 启用多路径创作（可选） ]  ○关  ●开
```

- **关闭**：现有生成流程完全不变（主时间线事件 + 主时间线推演记录）。
- **开启**：增加「素材空间」选择：
  - 主时间线（默认）
  - 某分支（下拉：`GET /api/worlds/{id}/branches`）
  并允许：
  1. 选方向 → 生成「不同选择下的后续走向」；
  2. 对同一前提生成多个变体（每个变体保存为独立章节草稿，标注 `space/branch` 来源）；
  3. 结果保存后，可「导入故事线」（阶段 C §4）。

### 3.2 后端兼容改动

`POST /api/writing/generate` 增加**可选**参数：

```json
{ "branch_id": "...", "direction_id": "...", "variant_label": "..." }
```

- 不传：行为与现在完全一致（`branch_id IS NULL`）。
- 传 `branch_id`：事件与推演记录按该分支作用域取（`branch_id = ?`），仍保留 `direction/perspective` 等业务参数。
- 章节写入 `stories` 时，新增可选来源标记（见 §4 的字段建议），不改变老字段语义。

### 3.3 成本与失败处理

- 变体生成 = 多次调用；前端需逐个展示，可中断。
- 沿用统一客户端与请求级配置；错误按 A3 统一。

## 4. 与故事线管理的连接（交付物接口）

多路径结果不自动变故事；必须用户显式「导入」。设计两个接口（阶段 D 实现）：

| 接口 | 作用 |
| --- | --- |
| `POST /api/stories/{story_id}/import-branch` | 把 `branch` 导入为一个「平行空间」：创建 `story_spaces`（`branch_id` 绑定），可选同时创建结局引用 |
| `POST /api/stories/{story_id}/import-ending` | 把 `simulation_endings` 记录导入为故事结局（保留来源 ID） |

导入规则：
- 幂等：同一 `branch_id` 在同一故事下只建一个空间（唯一约束）。
- 不复制快照：空间只存 `branch_id` 指针，状态仍由分支快照承载，避免双份数据。
- 不修改分支与主线事件。

## 5. 不做什么（明确边界）

- 不在 07/08 内重建方向/分支/推演逻辑。
- 不把多路径设为默认流程。
- 不删除 `/multipath` 旧入口与旧数据。
- 不让「应用分支」出现在 07/08 的一键流程里（覆盖主时间线风险高，保留在多路径页并二次确认）。
- 不因整合而改 `events.branch_id` 语义。

## 6. 验收标准（阶段 F 第 1 步）

1. 07 开关关闭时，网络请求与结果与改造前完全一致（回归 102 项通过）。
2. 07 开关开启后，可完成：选方向 → 建分支 → 分支推演 → 查看节点；主线推演仍可用。
3. 08 开关关闭时，生成请求不带新参数；开启后可基于分支素材生成，且章节数量 ≥ 基线。
4. 两个入口均使用访客 Key/模型（请求头生效）。
5. 导入故事线后，空间能显示其分支事件与结局，主时间线无新增污染。
