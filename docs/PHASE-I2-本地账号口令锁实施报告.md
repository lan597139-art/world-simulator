# I2 实施报告：本地账号口令锁与请求鉴权

日期：2026-11-11  
结论：**已实现单用户本地口令锁、会话 token、全局 API 鉴权与前端登录门**。  
不是多用户/多租户隔离；世界级 owner 已校验，其余资源的逐用户隔离仍待后续阶段。

---

## 1. 目标与边界

I1 只有 `local` 用户和 `owner_id`，没有认证。I2 补的是：

- 密码哈希与登录；
- 会话 token；
- 默认拒绝未登录的 `/api/*`；
- 前端首次初始化、登录、登出；
- 世界创建/读取/更新/删除的 owner 校验。

明确不做：

- 公开注册、多用户并存；
- 角色权限/团队共享；
- 密码找回、邮箱验证；
- 每个嵌套资源（人物/事件/分支）的逐用户授权。

## 2. 数据层（63 → 64 表）

## 3. 鉴权行为

- 默认开启；`WS_AUTH_DISABLED=1` 仅用于受控测试。
- 公开接口：`/api/health`、`/api/auth/status`、`/api/auth/setup`、`/api/auth/login`。
- 其余 `/api/*` 必须带 `Authorization: Bearer <token>`；否则 401。
- 会话过期/登出/用户停用立即失效。
- 登录失败统一提示，不暴露用户名是否存在。
- `WS_SETUP_TOKEN` 可选：公开部署首次初始化必须提供该令牌，避免第一个访客认领账号。
- 前端收到 401 会清理本地 token 并回到登录门。

## 4. 账号与归属

- 首次访问：`/api/auth/status` 返回 `setup_required=true`；初始化只允许一次。
- 初始化后 `local` 用户改为用户设定的用户名/显示名/密码；旧世界 owner 仍为 `local`，不丢数据。
- `GET /api/worlds` 只返回当前 owner 的世界 + 官方演示世界。
- 创建世界写入当前用户；读取/更新/删除校验 owner，不匹配返回 404（不泄露存在性）。
- `GET /api/users/me` 返回当前登录用户，不再是固定 `local`。

## 5. 前端

- `AuthGate`：初始化 / 登录 / 加载三态，包住整个应用；
- token 存 `localStorage`，请求桥自动加 `Authorization`；
- `退出登录` 位于侧栏底部；
- 登录失败、初始化令牌错误、会话失效均有提示；
- 原有 AI Key 请求头逻辑保持不变。

## 6. 测试

- 新增 `smoke_auth.py`：**13 项通过**（公开状态、未登录拒绝、错误密码、登录、me、业务访问、非法/过期 token、owner、登出失效、重复初始化/令牌保护）。
- 既有实时 HTTP 套件通过临时会话 token 访问，不绕过鉴权。
- 全量：**413 passed / 0 failed / 17 suites**。
- 迁移演练：27/27，**64 表**。
- 浏览器：初始化 → 进入应用；登出 → 登录门；重新登录 → 进入应用；token 存在时业务请求正常。
- `tsc`、`vite build` 通过。

## 7. 已知风险 / 未做

| 项 | 状态 | 说明 |
| --- | --- | --- |
| 多用户 | 未实现 | 只有单用户本地锁 |
| 嵌套资源 owner 校验 | 部分 | API 级登录已全量；世界级 owner 已校验，人物/事件等未逐项校验 |
| 登录限速/锁定 | 未实现 | 可被暴力尝试 |
| 密码找回 | 未实现 | 忘记密码只能改库 |
| token 存储 | localStorage | 有 XSS 时可能泄露；无 HttpOnly Cookie |
| CSRF | 低风险 | Bearer 头不随表单自动发送 |
| 公开部署初始化 | 需配置 | 未设 `WS_SETUP_TOKEN` 时首个访问者可初始化 |

## 8. 兼容性

- 旧世界、人物、事件、日记、传记、聊天数据均保留；
- 测试通过 `WS_AUTH_DISABLED=1` 保持既有业务回归；
- 生产默认开启鉴权；
- 旧 API 客户端必须加 Bearer token，否则 401。
