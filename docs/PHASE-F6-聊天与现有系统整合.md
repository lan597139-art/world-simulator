# 阶段 F6：聊天与现有系统整合（已实现）

把聊天从独立房间接入人物与事件体系；所有写回都必须由用户显式点击。

---

## 1. 入口

- 03 人物管理卡片新增「聊天」按钮：记录所选人物并跳到「AI 角色聊天」，聊天页自动选中该人物。
- 不改变 03 页面布局，仅在操作按钮组追加一枚。
- 聊天页仍可从人物下拉框直接开私聊/群聊。

## 2. 对话 → 事件

`POST /api/chat/threads/{id}/to-event`

- 取最近 N 条（默认 10）消息，按「用户：/角色名：」生成记录；
- 创建**主时间线事件**：`domain=["对话"]`、`scale="个人"`、参与者为会话角色；
- 标题默认「会话名 · 对话记录」，极性/强度可传，默认稳定/低；
- 空会话拒绝（409），极性/强度非法拒绝（422）。
- 事件进入 05 事件管理，可被时间线、写作、故事线正常引用。

## 3. 对话 → 人物经历

`POST /api/chat/threads/{id}/to-experience`

- 仅允许会话内角色；
- 向 `characters.life_history` 追加：
  `{event, result, source:"chat", thread_id, recorded_at}`；
- 上限 200 条，只追加不覆盖；
- 这是**显式写回正式档案**，不会在普通聊天时自动发生。

## 4. 页面

- 会话有消息时出现「整理为事件」；
- 展开可改标题、勾选「写入角色经历」，点击保存；
- 成功提示包含事件名与是否写入经历。

## 5. 实测证据

- `smoke_chat.py`：**46 项全通过**，新增 6 项：整理为事件、描述含对话记录（显示名）、非法极性、写入经历、来源标记、非会话角色拒绝、空会话拒绝。
- 浏览器：官方世界 03 → 韩立卡片「聊天」→ 跳转聊天页且下拉自动选中「韩立」。
- 全量回归：**327 passed / 0 failed**；`tsc`、`vite build` 通过。

## 6. 边界

- 事件描述是对话记录整理，不是 AI 润色摘要；避免额外编造。
- 写入经历使用会话前 8 条，长会话只截取最近部分。
- 不自动修改关系、六轴、运行态；避免聊天副作用污染世界。
- 官方世界已有 3 个空的「与南宫婉的对话」会话（用户侧产生），未改动。
