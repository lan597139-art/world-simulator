# 阶段 F5：AI 角色群聊调度（已实现）

在 F4 私聊基础上增加群聊：**建群、选人发言、顺序、隔离上下文、计划留痕**。

---

## 1. 调度机制

1. 用户消息先落库；
2. 调度器读取群成员：称呼、身份、主导引擎、发言策略；
3. 要求模型只返回 JSON：本轮 1–3 位发言者及顺序；
4. 规则校验：成员必须存在、去重、`silent` 跳过、`when_mentioned` 仅在点名时发言；
5. 解析失败或非法 → **规则兜底**（点名者优先，否则按成员顺序取 2 人），并标记 `fallback`；
6. 按顺序逐位生成回复；每位角色看到：
   - 自己的历史发言 → `assistant`；
   - 其他角色发言 → `user` 并加「【角色名】」前缀，避免身份混淆；
   - 最近 20 条上下文 + 自己的记忆；
7. 每位回复 1–3 句，禁止代答其他角色；回复即时落库，后续角色能看到；
8. 每轮写入 `chat_plans`（原始输出、最终名单、是否兜底、模型），便于审计。

成本上限：一轮最多 1 次调度 + 3 次角色回复。

## 2. 接口

```
POST /api/chat/threads/{id}/turns
body: { content }
resp: { user_message, replies[], plan[] }
```

- 私聊调用该接口返回 409；
- 群聊使用 `/messages` 也返回 409；
- 少于 2 名成员拒绝；
- 归档会话拒绝。

## 3. 页面

- 左侧新增「新建群聊（选 2–6 人）」，勾选人物即可建群；
- 群聊输入框启用，发送后按调度顺序展示多条回复；
- 忙碌提示改为「群聊调度中…」；
- 记忆面板按角色汇总本轮片段。

## 4. 实测证据

- `smoke_chat.py`：**39 项全通过**，其中群聊 8 项：多角色发言、计划返回、消息落库、每位发言者记忆、计划持久化、非法计划兜底、兜底标记、私聊拒绝 turns。
- 真实 AI 端到端（临时世界，已清理）：三人群「丙、乙、甲」，提问「墨居仁最近在药园鬼鬼祟祟，你们觉得他想干什么？」：
  - 甲（V=80）：「（压低声音）我前些天看见他往药园深处去了……手里好像拿着个布袋。」
  - 乙（O=80）：「（微微皱眉）擅自进入药园深处已违反门规。」
  - 调度器选择 2 人，丙未发言；两条记忆分别生成。
- 全量回归：**320 passed / 0 failed**；`tsc`、`vite build` 通过。

## 5. 边界与未完成

- 调度只看设定、策略与最近对话，不看完整关系网/六轴；避免额外上下文成本。
- 没有 @点名 UI（按文本包含名字识别）；没有打断、抢话、多轮连续对话。
- 发言顺序只由一次调度决定，不支持角色间自主续聊。
- 对话转经历/事件、角色成长回写、与正式档案同步 → F6。
- 真实多人长对话的成本/延迟未做配额；一轮最多 4 次模型调用。
